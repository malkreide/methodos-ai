# Pinned versions for CI and local development.
#
# Why this file exists: CI once went red because numpy shipped a 3.12-only
# release whose type stubs mypy could not parse under the configured Python
# version. Nothing in the repo had changed. Pinning the environment keeps a
# dependency release from turning a green branch red on its own.
#
# This is a *constraints* file, not a requirements file: it only says which
# version to use IF a package gets installed. pyproject.toml keeps open ranges
# so `pip install methodos` stays flexible for downstream users — the pins
# apply to this repo's CI and contributors only.
#
#     pip install -e ".[dev,mcp]" -c constraints.txt
#
# Covers `dev` and `mcp` on Python 3.11 and 3.12 (the CI matrix). The rule is
# simply what CI installs: `mcp` is pinned because CI type-checks and imports
# it, `local` is not because torch/sentence-transformers resolve differently
# per platform and never reach CI.
#
# Not pinned is not the same as ignored, though. `make install` installs
# ".[dev,local]" against this file, so a pin here must not *contradict* the
# local extra where the two share a transitive dependency — see `tokenizers`.
#
# To refresh (Dependabot also opens PRs for this file):
#     python -m venv /tmp/pin && /tmp/pin/bin/pip install -e ".[dev,mcp]"
#     /tmp/pin/bin/pip freeze --exclude-editable | sort
# Re-run under both 3.11 and 3.12; add a marker for anything that differs.
#
# Do NOT paste that freeze in wholesale. It is produced without the `local`
# extra, so it will happily propose a `tokenizers` that only the local extra
# objects to — the exact regression #20 fixed. Diff it against this file,
# reapply the commented pins below, and then prove the result still works for
# the extra the freeze could not see:
#     pip install --dry-run -e ".[dev,local,mcp]" -c constraints.txt
