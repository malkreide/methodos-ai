# Kano Model

Not all attributes buy the same satisfaction. Some earn nothing when present
and fury when absent; others delight precisely because nobody expected them.

| Category | Present | Absent |
|---|---|---|
| **Must-be** | no credit | anger |
| **One-dimensional** | more is better | proportionate disappointment |
| **Attractive** (delighter) | delight | not missed |
| **Indifferent** | nothing | nothing |
| **Reverse** | annoyance | preferred |

Delighters decay. Today's surprise is next year's must-be.

## When to use

- Deciding how much to invest in polish versus novelty
- A team cannot tell table stakes from differentiators
- Heavy investment in quality moved no satisfaction metric and nobody knows why

## When *not* to use

- Without access to real customers — the questionnaire is the method
- To rank by cost or effort; Kano says nothing about either
- For internal tooling with a captive audience

## Facilitation outline (survey over 2–4 weeks)

1. Choose 10–20 attributes. More than that and completion rates collapse.
2. For each, ask the functional and dysfunctional pair:
   "How do you feel if it *is* present?" / "How do you feel if it is *not*?"
3. Use the standard five answers, not a free-text box.
4. Map each answer pair to a category via the Kano table.
5. Report per segment. Categories differ sharply between segments.
6. Combine with an effort estimate — Kano ranks satisfaction, not value for money.

## Common pitfalls

- Guessing the categories in a workshop instead of surveying
- Averaging across segments, which erases the finding
- Over-investing in must-be attributes that are already adequate
- Treating today's delighter as permanently differentiating
